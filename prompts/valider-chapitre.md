# Achever provisoirement un chapitre et apprendre de son élaboration

L’auteur valide {chapter}. La version précise, son commentaire, les dernières corrections humaines, les archives et les variantes sont dans {evidence}. Lis ce document intégralement, le chapitre conservé et les retours pertinents de Tracking/Inputs.md et Tracking/Conversation.md. Examine les versions utiles de l’inventaire, les réactions et les relevés de corrections. Distingue ce que tu peux établir de ce qui manque ; aucune archive ne constitue à elle seule une preuve de rejet. Le texte approuvé prime sur les brouillons et sur ta mémoire de la conversation.

Écris le bilan dans {report} : ce qui a été produit, ce qui a été conservé, ce qui a été explicitement écarté, ce que l’auteur a ajouté, coupé ou réécrit, et l’effet concret de ces choix. Appuie les constats sur des citations exactes et les fichiers sources. Analyse particulièrement le dernier diff humain, même si l’auteur n’a pas demandé une révision avant de valider. N’attribue pas ses retouches à Codex. Distingue une amélioration du texte, une préférence locale, une décision de continuité et une préférence réutilisable. Si le texte garde des commentaires non résolus, consigne-les comme réserves ; ne prétends pas les avoir résolus.

Déduis des consignes pour la suite quand les preuves le permettent. Pour chacune : formulation opératoire, exemple positif ou contre-exemple, portée, preuve et degré de certitude. Une coupe isolée ne devient pas une interdiction universelle. Conserve les hypothèses comme hypothèses dans le bilan. Intègre les règles d’écriture suffisamment étayées dans {bibleFolder}/Style et les décisions de construction dans {bibleFolder}/Plan ; les faits ou traits de personnages dans leurs fiches propres. Préserve les consignes compatibles, supprime les doublons, relève les contradictions sans choisir arbitrairement. Les fiches donnent l’état utile actuel ; les justifications et l’histoire restent dans Tracking/Provenance.md. Mets à jour la rubrique « Consignes actives » de Tracking/Connaissances.md pour que les prochains échanges utilisent cette compréhension. Si aucune règle nouvelle n’est justifiée, explique-le dans le bilan et conserve les règles existantes.

Analyse les apports de l’auteur transmis avec cette demande et confirme leur traitement avec analyser_inputs. Une simple commande de validation sans précision supplémentaire peut être classée sans-impact, avec la raison qu’elle approuve une version sans introduire de règle littéraire nouvelle ; un commentaire substantiel doit être traité. Ne réécris aucun chapitre, aucune source Model, aucun brainstorm. Utilise ecrire_fichier pour le bilan et les fiches concernées. Le plugin protège la version approuvée et l’état de validation. Toute modification ultérieure du chapitre rendra cette validation historique ; elle n’interdit pas une reprise.

Dans le chat, confirme brièvement la version validée, donne le lien du bilan et les principaux enseignements réellement enregistrés. Signale les incertitudes ou un échec ; une approbation de l’auteur ne prouve pas que l’analyse a été effectuée.
